## 구현 결과

사진과 TXT를 확장자 앞의 같은 이름으로 자동 연결한다. 대소문자를 구분하지 않는다.
ZIP은 distinct/images와 distinct/bbs만 읽는다. 파일을 임의 경로에 압축 해제하지 않는다.
사진 1~10장을 분석할 수 있고, 10장이 아니면 안내한다.
ZIP에서는 기본으로 이름순 10장을 선택하며 사용자가 바꿀 수 있다.

클래스 0은 개별 세포, 1은 뭉침이며 1은 정답 개수에서 제외한다.
알 수 없는 클래스는 추정하지 않는다. 누락·중복 TXT, 중복 사진, 빈 주석,
범위 밖/0크기/중복 bbox, 손상 이미지, 640×640 이외 사진을 오류로 안내한다.
한 사진이 실패해도 나머지는 분석한다. 대응 사진이 없는 TXT도 오류 행으로 남긴다.
오류 행은 평균에서 제외하며 정답·오차를 채우지 않는다.

표에는 사진별 자동 계수·정답·절대오차·백분율오차·뭉침 주석 수가 나온다.
CSV는 오류 행과 설정, 알고리즘 버전, 이미지/TXT SHA-256도 포함한다.
한국어 엑셀 호환 UTF-8 BOM을 붙이고 파일명의 수식 실행 문자를 무력화한다.
입력이나 설정이 바뀌면 이전 결과 다운로드를 숨기고 재실행을 안내한다.

## 실제 10장 결과 (기본 설정 고정)

선정: distinct 이미지 파일명을 문자열 이름순으로 정렬한 첫 10장.
무작위 대표 표본이 아니며, 성능을 보고 유리한 사진을 고르지 않았다.
설정: auto / sensitivity 50 / min_area 18 / max_area 2200. 전부 gray로 판정됨.

## 발견한 오류와 남은 문제

- 계수판 격자선·배경 무늬가 세포 후보로 검출되는 것을 10장 오버레이에서 확인했다.
  특히 1.png, 102.png, 109.png에서 과다 계수가 크다.
- 원본 335.txt, 515.txt는 빈 파일이다. 정답 0개로 단정하지 않는다.
- distinct에도 뭉침 클래스가 있다. 클래스 1을 개별 세포 1개로 세면 잘못된 정답이 된다.
- 기존 README에 적힌 준비 스크립트·테스트가 실제 main에는 없어 새로 추가했다.
  이전 V1의 ‘11개 테스트 통과’ 기록을 이번 실행 결과로 간주하지 않았다.
- 파일명이 같아도 서로 다른 이미지/TXT를 업로드하면 자동으로 알아낼 수 없다.
  일부 행만 빠진 유효 TXT, 원래 주석의 생물학적 정확성도 형식 검사로 보장하지 못한다.
- ZIP 전체를 메모리로 읽으므로 메모리가 제한된 서버에서는 압축 해제 후 10장 개별 업로드를 권장한다.
- V1의 기존 run_windows.bat도 저장소에 없다. README 상단의 Python 실행 명령을 이용한다.
