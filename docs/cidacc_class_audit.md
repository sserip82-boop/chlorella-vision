# CIDACC 클래스 확인 기록

확인일: 2026-11-18. 대상: Zenodo record 13219972, `CIDACC-dataset.zip`.
배포 ZIP MD5(배포처 제공): `70efb2660fdc91737e8f1476d064100d`.

## 확인 방법과 결론

배포 ZIP의 중앙 디렉터리를 조회하고, 628개 bbs TXT를 모두 읽었다.
각 파일의 ZIP CRC32를 확인했다. 이후 전체 ZIP 다운로드도 완료하여
MD5 `70efb2660fdc91737e8f1476d064100d`가 배포처 값과 일치함을 확인했다.
공식 클래스 이름 사전(classes.txt / YAML 등)은 ZIP에서 찾지 못했다.
따라서 아래 결론은 **실제 주석 집계와 논문 수치의 일치, 이미지 대조에 근거한 해석**이다.

| 폴더 | TXT 수 | 클래스 0 | 클래스 1 |
|---|---:|---:|---:|
| distinct | 464 | 2,732 | 39 |
| clusters | 164 | 3,076 | 144 |
| 전체 | 628 | 5,808 | 183 |

논문은 개별 세포 주석을 5,808개, 뭉침 주석을 183개로 보고한다.
두 수치가 정확히 대응하므로 `0 = 개별 세포`, `1 = 뭉침`으로 해석한다.
`distinct`에도 클래스 1이 있으므로 TXT의 모든 줄을 세는 방식은 잘못된 정답을 만든다.
클래스 1은 노이즈라고 임의로 부르지 않으며, 개별 세포 수로 환산하지 않는다.

실제 `distinct/images/101.png`와 `bbs/101.txt`, `masks/101.png`를 대조했다.
클래스 0 상자 6개는 개별 세포 위치에 대응한다.
오른쪽 가장자리 클래스 1 상자는 복수/붙은 세포 영역을 감싸며 개별 수를 확정하지 않는다.
마스크는 세포 영역 참고용이며 클래스 번호 사전으로 사용하지 않았다.

프로그램은 이 버전의 CIDACC 데이터에 한해 위 의미를 적용한다.
알 수 없는 클래스, 빈 TXT, 손상된 좌표는 정답과 오차율을 계산하지 않는다.
다른 데이터셋 또는 변경된 CIDACC 버전에 이 클래스 의미를 그대로 적용하면 안 된다.
같은 이름이지만 다른 사진의 TXT, 일부 행이 빠진 유효 TXT는 형식 검사만으로 확인할 수 없다.
CSV의 이미지·주석 SHA-256으로 재현 시 파일을 비교할 수 있다.

전체 TXT의 좌표 형식 검사는 통과했지만 `distinct/bbs/335.txt`, `515.txt`는 비어 있었다.
빈 주석은 누락 여부가 확인되지 않았으므로 V2에서 오류로 처리한다.
